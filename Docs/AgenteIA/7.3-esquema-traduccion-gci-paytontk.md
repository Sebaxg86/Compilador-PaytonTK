# Esquema de Traducción de Generación de Código Intermedio para PaytonTK

Este documento contiene el esquema de traducción de **Generación de Código Intermedio** de PaytonTK, usando el enfoque clásico del Ing. Gil y del Libro del Dragón: producciones con acciones numeradas `{n}` y tabla separada de acciones de traducción.

La implementación actual ya no genera los objetos `Cuadruplo` directamente desde las acciones de `GenCodigoInt`. El flujo real quedó separado en dos pasos:

```txt
GenCodigoInt
  recorre la gramática y emite C3D textual en codigoIntermedio

Cuadruplos
  convierte cada sentencia de C3D textual a objetos Cuadruplo
```

Por eso, en este esquema las acciones de traducción emiten **sentencias de C3D textual**. La tabla de cuádruplos se construye después, al final de `GenCodigoInt.generar()`, con:

```java
cmp.cua.generarDesdeCodigoIntermedio(codigoIntermedio);
```

## Acciones previas al esquema

Antes de aplicar este esquema de traducción se asume lo siguiente:

1. El programa fuente ya fue aceptado por las etapas léxica, sintáctica y semántica.
2. La tabla de símbolos ya contiene:
   - identificadores declarados,
   - constantes tipificadas,
   - firmas de funciones,
   - ámbitos registrados por la etapa semántica.
3. La etapa de GCI no vuelve a comprobar tipos ni declaraciones; solo genera C3D.
4. Las producciones de declaraciones, parámetros formales y tipos se conservan en el traductor por fidelidad al parser actual, pero **no emiten C3D ejecutable**.

## Flujo real de la etapa

El flujo implementado actualmente es:

1. `Compilador.generarCodigoInt()` reinicia errores, restablece el buffer de entrada, inicializa `cmp.cua` y llama a `gci.generar()`.
2. `GenCodigoInt.generar()` reinicia temporales, etiquetas y la lista `codigoIntermedio`.
3. El traductor descendente recursivo recorre el programa con los mismos no terminales principales del parser.
4. Las acciones llaman a `emite(op, arg1, arg2, resultado)`.
5. `emite(...)` formatea la instrucción como texto de C3D y la agrega a `codigoIntermedio`.
6. Si existe `iuListener`, también muestra esa sentencia textual en la interfaz.
7. Al terminar el recorrido, `GenCodigoInt` llama a `cmp.cua.generarDesdeCodigoIntermedio(codigoIntermedio)`.
8. `Cuadruplos` limpia la tabla anterior, analiza cada sentencia textual y crea los objetos `Cuadruplo`.

## Convención de presentación

- Las producciones llevan marcas de acción numeradas, por ejemplo `{1}`, `{2}`, `{3}`.
- Cada número corresponde a una acción de traducción en una tabla separada.
- Se usa `nil` para representar la ausencia de un lugar de resultado.
- Se mantienen los nombres de atributos usados por la implementación: `.lugar`, `.h`, `.verdadera`, `.falsa`, `.siguiente`, `.comienzo` y `.argc`.
- Para listas de argumentos se usa `.argc`.
- En el código real, un token se convierte a lugar con `referencia(token)`.
- `referencia(token)` devuelve:
  - `[n]` si el token tiene entrada en la tabla de símbolos,
  - el lexema directo si no tiene entrada.
- `PROGRAMA` y `PROPOSICIONES_OPTATIVAS` funcionan como concatenación directa de C3D.
- En el código Java, los no terminales con prima se implementan con sufijo `_2`; por ejemplo, `ARGUMENTOS'` aparece como `ARGUMENTOS_2`.
- El cierre de bloque `::` se consume como dos tokens `:` porque el lexer actual entrega `::` separado.

Como la gramática de PaytonTK permite mezclar `FUNCION` y `PROPOSICION` en el nivel superior, cada función se traduce con un salto de escape previo:

```txt
goto Lsalto
Lfunc:
  ... cuerpo de la función ...
Lsalto:
```

## Convención de emisión de C3D

Las acciones llaman a `emite(op, arg1, arg2, resultado)`, pero esta rutina **no agrega un objeto `Cuadruplo`**. Primero formatea una sentencia textual de C3D:

| Acción lógica | C3D textual emitido |
| --- | --- |
| `emite("+", x, y, t1)` | `t1 := x + y` |
| `emite("*", x, y, t2)` | `t2 := x * y` |
| `emite(":=", x, "", y)` | `y := x` |
| `emite("label", "", "", L1)` | `L1:` |
| `emite("goto", "", "", L2)` | `goto L2` |
| `emite("if<", x, y, L3)` | `if x < y goto L3` |
| `emite("param", x, "", "")` | `param x` |
| `emite("call", f, n, "")` | `call f, n` |
| `emite("call", f, n, t1)` | `t1 := call f, n` |
| `emite("return", x, "", "")` | `return x` |
| `emite("return", "", "", "")` | `return` |
| `emite("print", x, "", "")` | `print x` |

## Conversión posterior a cuádruplos

Después de generar todo el C3D textual, `Cuadruplos.generarDesdeCodigoIntermedio(...)` convierte cada sentencia a un objeto `Cuadruplo(op, arg1, arg2, resultado)`.

La conversión real de la implementación actual es:

| C3D textual | Cuádruplo generado |
| --- | --- |
| `t1 := x + y` | `Cuadruplo("+", x, y, t1)` |
| `t2 := x * y` | `Cuadruplo("*", x, y, t2)` |
| `y := x` | `Cuadruplo(":=", x, "", y)` |
| `L1:` | `Cuadruplo("", "", "", L1)` |
| `goto L2` | `Cuadruplo("goto", "", "", L2)` |
| `if x < y goto L3` | `Cuadruplo("<", x, y, L3)` |
| `if x >= y goto L4` | `Cuadruplo(">=", x, y, L4)` |
| `param x` | `Cuadruplo("param", x, "", "")` |
| `call f, n` | `Cuadruplo("call", f, n, "")` |
| `t1 := call f, n` | `Cuadruplo("call", f, n, t1)` |
| `return x` | `Cuadruplo("return", x, "", "")` |
| `return` | `Cuadruplo("return", "", "", "")` |
| `print x` | `Cuadruplo("print", x, "", "")` |

Nota importante: las etiquetas no quedan con operación `"label"` en la tabla actual. El objeto se guarda con `op == ""` y la etiqueta en `resultado`.

## Funciones auxiliares usadas

- `emite(op, arg1, arg2, resultado)` agrega una sentencia textual a `codigoIntermedio`.
- `formatearC3D(op, arg1, arg2, resultado)` traduce los cuatro campos lógicos a texto C3D.
- `tempnuevo()` devuelve un temporal distinto en llamadas sucesivas: `t1`, `t2`, `t3`, ...
- `etiqnueva()` devuelve una etiqueta distinta en llamadas sucesivas: `etiq1`, `etiq2`, `etiq3`, ...
- `etiqfun(entrada)` devuelve la etiqueta interna asociada a una función.
- `referencia(token)` devuelve `[entrada]` cuando el token está en la tabla de símbolos, o el lexema directo si no tiene entrada.
- `esNil(lugar)` reconoce `nil`, cadena vacía o `null` como ausencia de resultado.

La función `etiqfun(entrada)` tiene esta convención real:

- si recibe `[n]`, devuelve `fun` seguido de `n`;
- si recibe un lexema directo, devuelve `fun_lexema`;
- si recibe vacío o `null`, devuelve `fun0`.

Ejemplo:

```txt
id de función con entrada [5]  -> fun5
id directo suma_total          -> fun_suma_total
```

## Atributos usados

- `.lugar`
  - Lugar donde queda el resultado de una expresión.
- `.h`
  - Atributo heredado usado para propagar el lugar parcial en expresiones o el identificador base en asignaciones y llamadas.
- `.verdadera`
  - Etiqueta de salida cuando una condición es verdadera.
- `.falsa`
  - Etiqueta de salida cuando una condición es falsa.
- `.siguiente`
  - Etiqueta de salida al terminar una proposición de control.
- `.comienzo`
  - Etiqueta inicial de un ciclo `while`.
- `.argc`
  - Cantidad de argumentos actuales emitidos por una llamada.

## Producciones con acciones numeradas

```txt
PROGRAMA                    -> INSTRUCCION PROGRAMA {1} | ϵ {2}

INSTRUCCION                 -> FUNCION {3} | PROPOSICION {4}

FUNCION                     -> def id {5} ( ARGUMENTOS ) : TIPO_RETORNO
                               PROPOSICIONES_OPTATIVAS return RESULTADO {6} :: {7}

ARGUMENTOS                  -> TIPO_DATO id ARGUMENTOS' {8} | ϵ {9}

ARGUMENTOS'                 -> , TIPO_DATO id ARGUMENTOS' {10} | ϵ {11}

DECLARACION_VARS            -> TIPO_DATO id DECLARACION_VARS' {12}

DECLARACION_VARS'           -> , id DECLARACION_VARS' {13} | ϵ {14}

TIPO_RETORNO                -> void {15} | TIPO_DATO {16}

TIPO_DATO                   -> int {17} | float {18} | string {19}

RESULTADO                   -> EXPRESION {20} | void {21}

PROPOSICIONES_OPTATIVAS     -> PROPOSICION PROPOSICIONES_OPTATIVAS {22} | ϵ {23}

PROPOSICION                 -> DECLARACION_VARS {24}
                            | id {25} PROPOSICION' {26}
                            | if {27} CONDICION : {28} PROPOSICIONES_OPTATIVAS
                              else : {29} PROPOSICIONES_OPTATIVAS :: {30}
                            | while {31} CONDICION : {32}
                              PROPOSICIONES_OPTATIVAS :: {33}
                            | print ( EXPRESION ) {34}

PROPOSICION'                -> opasig EXPRESION {35}
                            | ( LISTA_EXPRESIONES ) {36}

LISTA_EXPRESIONES           -> EXPRESION {37} LISTA_EXPRESIONES' {38} | ϵ {39}

LISTA_EXPRESIONES'          -> , EXPRESION {40} LISTA_EXPRESIONES' {41} | ϵ {42}

CONDICION                   -> EXPRESION oprel EXPRESION {43}

EXPRESION                   -> TERMINO {44} EXPRESION' {45} | literal {46}

EXPRESION'                  -> opsuma TERMINO {47} EXPRESION' {48} | ϵ {49}

TERMINO                     -> FACTOR {50} TERMINO' {51}

TERMINO'                    -> opmult FACTOR {52} TERMINO' {53} | ϵ {54}

                            | num {57}

                            | ( EXPRESION ) {59}

```

## Observaciones de implementación

- Este esquema corresponde al comportamiento actual de `GenCodigoInt.java` y `Cuadruplos.java`.
- `GenCodigoInt.java` conserva el estilo de traductor predictivo recursivo dirigido por sintaxis.
- `GenCodigoInt.java` emite C3D textual, no objetos `Cuadruplo`.
- `Cuadruplos.java` es la clase responsable de transformar el C3D textual en la tabla de cuádruplos.
- No se construye AST.
- No se usa notación prefija, polaca o postfija como representación intermedia obligatoria.
- La precedencia aritmética queda resuelta por la gramática de `EXPRESION`, `TERMINO` y `FACTOR`.
- Las llamadas a función emiten primero sus `param` y luego la sentencia `call`.
- Las proposiciones `if` y `while` generan sus propias etiquetas de control dentro del traductor descendente recursivo.
- Los lugares de identificadores, literales y constantes salen de la tabla de símbolos como referencias `[n]` cuando existe una entrada asociada.
- Los temporales `t1`, `t2`, etc. no se agregan a la tabla de símbolos durante GCI; son nombres internos del C3D.
- El generador de código objeto consume la tabla de cuádruplos ya construida por `Cuadruplos`.
