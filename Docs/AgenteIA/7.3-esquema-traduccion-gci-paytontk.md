# Esquema de Traducción de Generación de Código Intermedio para PaytonTK

Este documento contiene el esquema de traducción de **Generación de Código Intermedio** de PaytonTK, usando el enfoque clásico del Ing. Gil y del Libro del Dragón: producciones con acciones numeradas `{n}` y tabla separada de acciones de traducción.

## Acciones previas al esquema

Antes de aplicar este esquema de traducción se asume lo siguiente:

1. El programa fuente ya fue aceptado por las etapas léxica, sintáctica y semántica.
2. La tabla de símbolos ya contiene:
   - identificadores declarados,
   - constantes tipificadas,
   - firmas de funciones.
3. La etapa de GCI no vuelve a comprobar tipos ni declaraciones; solo genera C3D.
4. Las producciones de declaraciones y tipos se conservan en el traductor por fidelidad al parser actual, pero **no emiten cuádruplos**.

## Convención de presentación

- Las producciones llevan marcas de acción numeradas, por ejemplo `{1}`, `{2}`, `{3}`.
- Cada número corresponde a una acción de traducción en una tabla separada.
- Se usa `nil` para representar la ausencia de un lugar de resultado.
- Se mantienen los nombres de atributos clásicos: `.lugar`, `.h`, `.verdadera`, `.falsa`, `.siguiente`, `.comienzo`.
- Para listas de argumentos se usa además `.argc`.
- En este documento se escribe `id.entrada`, `num.entrada`, `num.num.entrada` y `literal.entrada` siguiendo la notación de los apuntes.
- `PROGRAMA` y `PROPOSICIONES_OPTATIVAS` funcionan como concatenación directa de código.
- Como la gramática de PaytonTK permite mezclar `FUNCION` y `PROPOSICION` en el nivel superior, cada función se traduce con un salto de escape previo:
  - `goto Lsalto`
  - `label Lfunc`
  - `... cuerpo de la funcion ...`
  - `label Lsalto`

## Convención de emisión a cuádruplos

La salida esperada de la etapa es una secuencia de objetos `Cuadruplo(op, arg1, arg2, resultado)`.

Se usará la siguiente convención:

- Operación binaria:
  - `Cuadruplo("+", x, y, t1)`
  - `Cuadruplo("*", x, y, t2)`
- Asignación:
  - `Cuadruplo(":=", x, "", y)`
- Etiqueta:
  - `Cuadruplo("label", "", "", L1)`
- Salto incondicional:
  - `Cuadruplo("goto", "", "", L2)`
- Salto condicional:
  - `Cuadruplo("if<", x, y, L3)`
  - `Cuadruplo("if>=", x, y, L4)`
- Parámetro:
  - `Cuadruplo("param", x, "", "")`
- Llamada sin valor de retorno:
  - `Cuadruplo("call", f, n, "")`
- Llamada con valor de retorno:
  - `Cuadruplo("call", f, n, t1)`
- Retorno con valor:
  - `Cuadruplo("return", x, "", "")`
- Retorno vacío:
  - `Cuadruplo("return", "", "", "")`
- Impresión:
  - `Cuadruplo("print", x, "", "")`

## Funciones auxiliares usadas

- `emite(op, arg1, arg2, resultado)` agrega un cuádruplo a la lista de salida.
- `tempnuevo()` devuelve un temporal distinto en llamadas sucesivas: `t1`, `t2`, `t3`, ...
- `etiqnueva()` devuelve una etiqueta distinta en llamadas sucesivas: `etiq1`, `etiq2`, `etiq3`, ...
- `etiqfun(id.entrada)` devuelve la etiqueta fija asociada a una función.

## Atributos usados

- `.lugar`
  - Lugar donde queda el resultado de una expresión.
- `.h`
  - Atributo heredado usado para propagar el lugar parcial en expresiones o el identificador base en asignaciones y llamadas.
- `.verdadera`
  - Etiqueta de salida cuando una condición es verdadera.
- `.falsa`
  - Etiqueta de salida cuando una condición es falsa.
- `.siguiente`
  - Etiqueta de salida al terminar una proposición de control.
- `.comienzo`
  - Etiqueta inicial de un ciclo `while`.
- `.argc`
  - Cantidad de argumentos actuales emitidos por una llamada.

## Producciones con acciones numeradas

```txt
PROGRAMA                    -> INSTRUCCION PROGRAMA {1} | ϵ {2}

INSTRUCCION                 -> FUNCION {3} | PROPOSICION {4}

FUNCION                     -> def id {5} ( ARGUMENTOS ) : TIPO_RETORNO
                               PROPOSICIONES_OPTATIVAS return RESULTADO {6} :: {7}

ARGUMENTOS                  -> TIPO_DATO id ARGUMENTOS' {8} | ϵ {9}

ARGUMENTOS'                 -> , TIPO_DATO id ARGUMENTOS' {10} | ϵ {11}

DECLARACION_VARS            -> TIPO_DATO id DECLARACION_VARS' {12}

DECLARACION_VARS'           -> , id DECLARACION_VARS' {13} | ϵ {14}

TIPO_RETORNO                -> void {15} | TIPO_DATO {16}

TIPO_DATO                   -> int {17} | float {18} | string {19}

RESULTADO                   -> EXPRESION {20} | void {21}

PROPOSICIONES_OPTATIVAS     -> PROPOSICION PROPOSICIONES_OPTATIVAS {22} | ϵ {23}

PROPOSICION                 -> DECLARACION_VARS {24}
                            | id {25} PROPOSICION' {26}
                            | if {27} CONDICION : {28} PROPOSICIONES_OPTATIVAS
                              else : {29} PROPOSICIONES_OPTATIVAS :: {30}
                            | while {31} CONDICION : {32}
                              PROPOSICIONES_OPTATIVAS :: {33}
                            | print ( EXPRESION ) {34}

PROPOSICION'                -> opasig EXPRESION {35}
                            | ( LISTA_EXPRESIONES ) {36}

LISTA_EXPRESIONES           -> EXPRESION {37} LISTA_EXPRESIONES' {38} | ϵ {39}

LISTA_EXPRESIONES'          -> , EXPRESION {40} LISTA_EXPRESIONES' {41} | ϵ {42}

CONDICION                   -> EXPRESION oprel EXPRESION {43}

EXPRESION                   -> TERMINO {44} EXPRESION' {45} | literal {46}

EXPRESION'                  -> opsuma TERMINO {47} EXPRESION' {48} | ϵ {49}

TERMINO                     -> FACTOR {50} TERMINO' {51}

TERMINO'                    -> opmult FACTOR {52} TERMINO' {53} | ϵ {54}

FACTOR                      -> id {55} FACTOR' {56}
                            | num {57}
                            | num.num {58}
                            | ( EXPRESION ) {59}

FACTOR'                     -> ( LISTA_EXPRESIONES ) {60} | ϵ {61}
```

## Tabla de acciones de traducción

| No. Acción | Acción de Traducción |
| --- | --- |
| 1 | `PROGRAMA` concatena el código emitido por `INSTRUCCION` y por `PROGRAMA1`. No emite cuádruplos adicionales. |
| 2 | `PROGRAMA` vacío. No emite código. |
| 3 | `INSTRUCCION -> FUNCION`. No emite código adicional. |
| 4 | `INSTRUCCION -> PROPOSICION`. No emite código adicional. |
| 5 | `FUNCION.h := id.entrada ; FUNCION.siguiente := etiqnueva() ; emite("goto", "", "", FUNCION.siguiente) ; emite("label", "", "", etiqfun(FUNCION.h))` |

| 8 | `ARGUMENTOS` no emite cuádruplos. Los parámetros formales ya fueron procesados por la etapa semántica. |

| 11 | `ARGUMENTOS'` vacío. No emite código. |

| 39 | `LISTA_EXPRESIONES.argc := 0` |

## Observaciones de implementación

- Este esquema está pensado para implementarse en `GenCodigoInt.java` copiando la estructura de procedures del sintáctico actual y agregando acciones de traducción en los puntos indicados.
- No requiere construir AST, notación prefija ni notación postfija como estructuras intermedias obligatorias.
- La precedencia aritmética ya queda resuelta por la propia gramática de `EXPRESION`, `TERMINO` y `FACTOR`.
- Las llamadas a función emiten primero sus `param` y luego el cuádruplo `call`.
- Las proposiciones `if` y `while` generan sus propias etiquetas de cierre para mantenerse autocontenidas dentro del traductor descendente recursivo.
